# GitHub 与本地版本差异

> 对比时间：2026-09-08  
> 共同基线：`fc3a5d2`  
> GitHub `origin/main`：`ba335ad`，比本地基线多 18 个提交。

## 结论

两边不是单纯的新旧版本，而是从同一基线发展出的两组功能。不能用 GitHub 覆盖本地，也不能将本地强制推送覆盖 GitHub；应做功能级合并。

## GitHub 独有能力

| 范围 | 内容 | 合并决定 |
| ---- | ---- | -------- |
| 云端运行 | 知乎 HTTP 直连、Node 单端口 `standalone-server` | 保留，并接入本地新搜索策略 |
| 持久缓存 | 24 小时搜索缓存 | 保留，与本地内存缓存统一 |
| 用户反馈 | 评分、留言、用量记录与管理页 | 保留，不将密钥或完整用户输入写入公开仓库 |
| 浏览器历史 | 基于 `localStorage` 的“我的结果” | 与本地服务端研究档案并存，分别承担快速访问和持久版本管理 |
| 开发者配置 | 临时输入知乎 / AI key | 保留服务端内存覆盖能力，确保不落盘、不返回原文、不进 Git |

## 本地独有能力

| 范围 | 内容 | 合并决定 |
| ---- | ---- | -------- |
| 搜索 | 5 轮分层查询，每轮受 CLI 限制最多 10 条，最多 50 个去重来源 | 保留，HTTP 直连和 CLI 使用同一预算 |
| 首轮交互 | 转专业 / 转行识别、条件词典、证据化预填和按类型表单 | 保留 |
| 证据系统 | 连续引文、条件对照、13 个阶段、路径归类、三问结论 | 保留 |
| 转专业 | 官方网页 / PDF / Word 及附件、资格与成本检查 | 保留 |
| 转行 | 行业与职能分类、岗位要求汇总、6 条行动路径成本 | 保留 |
| 重新匹配 | 复用来源和已接受案例，0 知乎、0 DeepSeek 本地重算 | 保留 |
| 质量保障 | 103 项自动测试、40 题评测集、脱敏运行指标、产品台账 | 保留并用于合并验收 |

## 重叠与冲突区

| 文件 | GitHub 主要改动 | 本地主要改动 | 风险 |
| ---- | --------------- | --------------- | ---- |
| `app/workspace.tsx` | 首屏六字段、历史记录、反馈、管理员入口、临时 key | 条件表单、官方来源、决策对照、档案与版本比较 | 高 |
| `app/globals.css` | 远端新页面与导航样式 | 本地新工作区和响应式样式 | 高 |
| `server/api.mjs` | HTTP provider、反馈/管理接口、使用记录 | 首轮表单、官方来源、研究档案、重新匹配、脱敏指标 | 高 |
| `server/engine.mjs` | CLI / HTTP 双后端、临时 key、持久缓存 | 条件词典、五轮搜索、证据校验、路径与阶段、分析限制 | 高 |
| `README.md` | 部署与云端运行说明 | 当前算法、验证和安全边界 | 中 |

## 合并步骤

1. 在 `codex/sync-local-enhancements` 保存本地完整快照。
2. 合并 `origin/main`，对五个重叠核心文件做功能级整合。
3. 检查 `.env.local`、`.local/`、API key 和用户原文，确保均不进入 Git。
4. 运行全量测试、评测集、类型检查、生产构建和本地首页验收。
5. 合并通过后推送保护分支；不强制覆盖 GitHub `main`。
